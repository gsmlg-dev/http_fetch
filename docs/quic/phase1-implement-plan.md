## Ordered implementation and verification

1. Q-01: correct stream IDs, monotonic allocation, sparse opening, reassembly,
   final sizes and unique terminals. Verify pure regressions before and after.
2. Q-02: install authenticated parameters into runtime, apply asymmetric windows
   and connection accounting, and recover consumption-driven credit. Verify
   zero/default/asymmetric limits and gaps/reset/duplicate accounting.
3. Q-03: bounded application admission, actual protected-packet STREAM splitting,
   recoverable scheduling pressure and bounded recovery. Verify 16 KiB writes,
   MTU/varint boundaries, partial scheduling, new packet numbers and reclamation.
4. Q-04: consumer attachment and bounded delivery, readiness/accept metadata,
   stream half-close/cancellation and operation outcome resolution. Verify
   attachment ordering, small reads, owner death, deadlines and generations.
5. Q-05: all egress through I/O capabilities, application CRYPTO and unequal CID
   lengths; verify actual G-S source, dependency pin and clean release startup.
6. Q-06: pinned independent peer in both roles, dedicated test ALPN, concurrent
   streams, cumulative transfer, impairment, cancellation and finite resource
   evidence. Report G-T separately from future Abyss G-A/G-P1 acceptance.
